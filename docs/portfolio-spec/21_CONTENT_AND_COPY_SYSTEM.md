# Content and Copy System

## Tone

- Direct
- Specific
- Controlled
- Confident without exaggeration
- Technical where useful
- No agency clichés

## Prohibited phrases

Avoid:

- Cutting-edge solutions
- Seamless experiences
- Passionate developer
- Pixel-perfect everything
- Innovative digital solutions
- Award-winning
- Transforming ideas into reality
- Results-driven, unless results are shown
- Full-stack wizard
- Crafting magic

## Home copy hierarchy

### Identity

Who are you?

```text
Gurtejbir Singh
Designer & Developer
```

### Positioning

What do you do?

```text
I design and develop distinctive digital products and web experiences.
```

### Differentiation

Why you?

```text
I work across visual direction, interface design and implementation, keeping the idea coherent from concept to launch.
```

### Evidence

Selected work and case studies.

### Conversion

```text
Have something worth building properly?
```

## Project summaries

Project summaries should answer:

- What was built?
- For whom?
- Why does it matter?

Keep homepage summaries below 24 words where possible.

## Case-study writing

Use the following order:

1. Situation
2. Constraint
3. Decision
4. Implementation
5. Outcome
6. Reflection

Bad:

```text
We wanted to create a seamless and intuitive experience.
```

Better:

```text
Patients needed OPD timings and department information without calling the hospital, while staff needed a simple way to keep those details current.
```

## Honest status language

Use:

- Concept
- In development
- Client project
- Production
- Private beta
- Prototype
- Shipped

Do not call a prototype a live platform.

## CTA vocabulary

Primary:

- View project
- Read case study
- Start a conversation
- View all work
- Explore the system

Avoid:

- Learn more on every section
- Click here
- Get started when no onboarding exists

## Microcopy

Navigation should be literal.

Forms should explain:

- Required fields
- Submission status
- Error recovery
- Privacy expectations

## Resume copy

Use a short factual summary, not a biography repeated from About.

## Content maintenance

All dates, availability labels and project statuses must come from structured content where possible. Avoid hardcoded “2026” in multiple components.
