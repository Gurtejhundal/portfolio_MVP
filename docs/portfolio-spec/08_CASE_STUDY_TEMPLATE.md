# Reusable Case Study Template

## Principle

A case study must explain decisions and evidence. It is not a long screenshot dump.

## 1. Project hero

Include:

- Project number
- Project title
- Category
- Year
- One-sentence proposition
- Primary cover
- Live-site link when available
- Repository link only when appropriate

## 2. Metadata strip

- Role
- Services
- Duration
- Team
- Status
- Stack, compactly

Do not turn this into a badge wall.

## 3. Context

Explain:

- Who the project is for
- What situation existed
- What constraints mattered
- What the deliverable needed to accomplish

## 4. Problem

State the actual problem. Avoid vague claims such as “users wanted a seamless experience.”

## 5. Strategy

Describe:

- Information hierarchy
- Primary user journey
- Positioning
- Content strategy
- Scope decisions
- What was deliberately excluded

## 6. Creative direction / design system

Show:

- Typography
- Colour
- Layout
- Image language
- Motion principles
- Component logic

Use labelled images, not decorative screenshots only.

## 7. Key experience

Explain two to four important sequences:

- Hero/onboarding
- Discovery/navigation
- Core task
- Conversion/contact/appointment
- Admin workflow where relevant

## 8. Development

Explain honestly:

- Architecture
- Front-end system
- Back-end system
- Data model
- Deployment
- Performance
- Security
- Trade-offs

Do not present a prototype as a complete production platform.

## 9. Outcome

Use real evidence only:

- Shipped status
- Real client feedback
- Measured performance
- Accessibility improvements
- Operational improvements
- Lessons

When metrics do not exist, say so.

## 10. Reflection

Include:

- What worked
- What was difficult
- What would change in version two

This is more credible than fabricated perfection.

## 11. Credits

List collaborators and asset sources accurately.

## 12. Next project

Use a large visual transition to the next published project.

## Suggested media sequence

1. Cover
2. Full-width overview
3. Two-column detail pair
4. Mobile sequence
5. System/component view
6. Final large outcome image

Do not repeat the same device mockup six times.
